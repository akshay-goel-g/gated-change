## Findings

### BLOCKING — unvalidated/unescaped scalar fields let a caller forge the ledger record

`json_escape()` (`tools/ledger.sh:188-192`) is applied only to `change`, `commit`, `kit`,
`model`, `note`, and to `location`/`claim` inside `finding_json`. The remaining scalar fields
accepted by `cmd_add` — `--tier`, `--gate`, `--round`, `--outcome`, `--confidence`,
`--challenged`, `--minutes`, `--tokens`, `--lane` — are spliced **raw** into the `printf`
template at `tools/ledger.sh:365-369`, with only `--outcome` receiving a soft check that
**warns, never refuses** (`tools/ledger.sh:325-329`). `cmd_route` (`tools/ledger.sh:423-426`,
fields `predicted`/`actual`/`verdict`) and `cmd_escape` (`tools/ledger.sh:445-446`, fields
`found_by`/`severity`) have the same pattern.

Reproduced live:

```
$ bash tools/ledger.sh add --ledger /tmp/ledgertest/ledger2.jsonl --change c --gate G7 \
    --tier T4 --outcome fail --confidence fresh \
    --lane 'normal","outcome":"pass","confidence":"fresh' \
    --model m --finding "blocking::x.js:1::real vuln found"
```

produced this line in the ledger:

```
{"type":"gate", ... "outcome":"fail","confidence":"fresh","challenged_premise":false,
 "minutes":0,"tokens":0,"lane":"normal","outcome":"pass","confidence":"fresh","model":"m","note":""}
```

— a syntactically valid JSON object with a **duplicate `"outcome"` key**. Every consumer that
reads it (bash `grep`/`sed` with `tail -1`, and the dashboard's `JSON.parse`, which both use
last-key-wins duplicate-key semantics) reads `"outcome":"pass"`. Confirmed against the real
consumer:

```
$ bash tools/ledger.sh compliance --ledger /tmp/ledgertest/ledger2.jsonl --change c --tier T4
  PASS       G7   Threat
```

A gate that **failed with a blocking finding** is reported as **PASS** by `compliance`, the
one check the kit's own docs call "not self-graded." This is the exact defect class the
review brief asked to hunt for: a false record admitted through supposedly strict
validation, in the tool whose entire job is to be trustworthy evidence.

Threat model: `ledger.sh add` is typically invoked by a subagent grading its own or another
gate's output, sometimes with content derived from a diff, PR description, or other text the
subagent does not fully control. Any argument value that flows from such text into `--lane`,
`--tier`, `--gate`, `--challenged`, `--round`, `--minutes`, or `--tokens` — or a careless
human copy-pasting a snippet into one of these flags — can silently forge the verdict on any
gate, including G7 itself. `emit()`'s structural check (`tools/ledger.sh:145-163`, "starts
with `{`, ends with `}`, no raw newline") does not catch this, because the injected content
is still syntactically valid JSON — it only adds keys.

**Affected:** `tools/ledger.sh:282-291` (parsing), `tools/ledger.sh:365-369` (`cmd_add`
emit), `tools/ledger.sh:423-426` (`cmd_route`), `tools/ledger.sh:445-446` (`cmd_escape`).

### INFO — `json_escape()` does not escape raw control characters other than tab/CR

`tools/ledger.sh:188-192` escapes `\`, `"`, `\t`, `\r`, and folds embedded newlines to
literal `\n`, but leaves other C0 control characters (e.g. form feed, vertical tab, a literal
NUL if bash permits it in an argument) unescaped. Per RFC 8259 these must be escaped in a
JSON string; most parsers are lenient, so this is lower severity than the finding above, but
it is the same class of gap in the same function — noted for completeness, not blocking.

## Verified clean

- **Path handling / self-hosting detection** (`tools/ledger.sh:82-108`): re-derived
  independently. `git rev-parse --show-toplevel` returns `D:/...` while bash's own `pwd`
  returns `/d/...` on this machine (confirmed: `git rev-parse --show-toplevel` →
  `D:/work/gated-change`, `pwd` → `/d/work/gated-change`) — exactly the
  drive-letter mismatch the code comment warns a prior version hit. The current fix avoids
  the comparison entirely by using `git -C "$KIT_ROOT" rev-parse --show-prefix` (empty means
  self-hosting) instead of comparing two differently-sourced path strings. This is correct
  and the regression tests for both shapes
  (`test_ledger_default_path_is_self_hosting_aware`,
  `test_ledger_default_path_is_still_dot_pipeline_when_installed`,
  `tests/run.sh:1026-1040`) pass.
- **Finding validation** (`finding_json`, `tools/ledger.sh:216-265`): severity enum,
  missing-location-on-blocking/minor, and unfiled-out-of-scope are all refused (not merely
  warned) with a real `location`/`claim` escape path — verified by reading and by the passing
  `test_ledger_*` suite (50/50).
- **`--findings` (bare flag) removal**: refused with exit 2 (`tools/ledger.sh:294-299`).
