## Trust boundary walk

`tools/dashboard/app.js` renders `LEDGERS` (raw `ledger.jsonl` lines, inlined into the
generated HTML by `tools/dashboard.sh`) and a user-dropped `.jsonl` file (drag/drop handler,
`wireDropzone()`, app.js:1057-1068). Both are attacker-reachable in principle: a ledger line is
free-form JSON written by whatever gate ran, and could in practice carry adversary-influenced
text (e.g. a `finding.claim` or `note` quoting attacker-supplied input from a reviewed diff).
The question this gate exists to ask: does any ledger-sourced string reach `innerHTML` without
passing through `escapeHtml()`/`attr()` first?

Traced every `.innerHTML =`/`insertAdjacentHTML` sink and every string concatenated into HTML
in app.js: `renderProjectsOverview` (app.js:457-482, project name via `escapeHtml`/`attr`),
`friendlyAsk`/`whyChip` (app.js:557-576, `reason`/`note`/`source` via `escapeHtml`/`attr`),
`friendlyResult`/`renderOutput` (app.js:578-615, 792-829, commit/severity strings via
`escapeHtml`), `renderOverviewTab`/`friendlyGateLine` (app.js:514-638, persona/sentence/detail
via `escapeHtml`), and the drawer (app.js:974-1042, `run.model`/`run.commit`/`run.note`/finding
`location`/`claim` all via `escapeHtml`, chip labels via `escapeHtml` inside `field()`). Every
sink found routes ledger-derived text through `escapeHtml()` or `attr()` before concatenation.
Two sinks use `.textContent`/DOM property assignment instead of string concatenation
(`sources`, `unparsed` banner, SVG `<title>` via `el()`+`textContent`), which is inherently
injection-safe regardless of escaping discipline.

**This commit itself touches no rendering/HTML-sink code.** Its diff is confined to
`computeStatus`/`buildExecutions`/the new `gate*AtOrBefore` helpers (pure data resolution, no
string building) plus a CSS rule and a legend string in `dashboard.sh` (static text, not
ledger-derived). No new sink was added, and no existing sink's escaping was altered or
weakened.

## Verdict

No injection surface was introduced or modified by 86f548e. The existing escaping discipline
(`escapeHtml`/`attr` on every ledger-derived string reaching `innerHTML`) is intact and
consistent throughout app.js as of this commit.

  "does the dashboard tell the truth about whether a gate ran" surface G7 exists to police.
  Filed as info here (out of this commit's diff, not adversarial-input-reachable) and reported
  in full under G4 in the review reply, since G4's card is the one that owns "same class of gap
  as the bug it fixes."
